# On-Page SEO Standard

Every generated Open WebGame site must pass this standard before it can be marked `deployment-ready`.

The objective is not to stuff keywords into a landing page. The objective is to make the page's topic, search intent, game entity, playable experience and supporting information unambiguous to both users and search engines.

## 1. Resolve the primary search intent

Before writing code, define:

```text
Primary entity: <exact game name>
Primary query intent: play | guide | controls | wiki | mixed
Primary keyword: <natural main query>
Secondary intents: <real supporting queries>
Canonical page purpose: <one sentence>
```

For a play-first homepage, the usual primary intent is:

```text
<Game Name>
play <Game Name>
<Game Name> online
```

Do not force `online`, `free`, `unblocked`, `download`, `codes`, `wiki` or other modifiers unless they are accurate and match real user intent.

## 2. URL and canonical

Production pages must have:

- one clean, stable URL
- lowercase, readable slugs
- hyphens instead of unnecessary parameters when routes are needed
- one self-referencing canonical URL
- HTTPS canonical URLs on production
- no `example.com`, localhost, staging or preview canonical left in production

Examples:

```text
https://examplegame.com/
https://examplegame.com/how-to-play/
https://examplegame.com/tips/
```

Avoid duplicate versions caused by trailing parameters, mixed casing or multiple routes for the same content.

## 3. Title tag

Every indexable page needs a unique, descriptive `<title>`.

Rules:

- include the exact game name naturally
- align with the page's actual intent
- put the most important concept early
- do not repeat the same keyword unnaturally
- do not use claims that are not verified
- keep it concise enough to read naturally in search results; there is no magic character count

Good patterns:

```text
Play <Game Name> Online — Guide, Controls & Tips
<Game Name> Beginner Guide — How to Play & Controls
<Game Name> Upgrades Guide — What to Unlock First
```

Bad patterns:

```text
<Game Name> <Game Name> Online Free Play Game Best Game
```

## 4. Meta description

Write a unique meta description for each important page.

It should:

- mention the game naturally
- explain what the user can do or learn on the page
- describe the real page content
- avoid fake urgency and keyword lists

Do not duplicate the same meta description across all routes.

## 5. H1 and heading structure

Every indexable page must have exactly one primary H1 in normal output.

For the homepage, the H1 must clearly identify the game and primary intent. A pure slogan is not enough.

Preferred:

```html
<h1>Play Scam Artist Online <span>Build a Shady Empire</span></h1>
```

Weaker:

```html
<h1>BUILD A SHADY EMPIRE</h1>
```

Use H2/H3 headings to describe real sections and secondary intents:

```text
H1: Play <Game Name> Online
H2: How to Play <Game Name>
H2: <Game Name> Controls
H2: Beginner Tips
H2: Frequently Asked Questions
```

Do not create headings solely to repeat keyword variants.

## 6. Above-the-fold topical clarity

The first visible section should make the page topic obvious without relying on the iframe.

Within the hero/intro, include naturally:

- exact game name
- what type of game it is
- what the player does
- whether it can be played on the page, if verified

Important game information must exist in normal HTML outside the iframe. Search engines should not need to understand the embedded game to understand the page.

## 7. Useful body content

A play-first site still needs useful, original supporting content.

Default useful sections include only verified topics:

- what the game is
- how to play
- controls
- real gameplay loop
- upgrades/resources/systems if they exist
- beginner tips
- browser/mobile compatibility when verified
- creator/developer information
- FAQ based on real first-session questions

Do not pad word count. There is no required minimum word count.

The page should be as detailed as necessary to satisfy the intent and no longer.

Lead with the answer a player came for. Use player-facing labels such as `Quick answer`, `How to play`, `Controls` and `Beginner tips`. Keep internal research labels such as `evidence ledger`, `verification state` or `source registry` out of public copy; preserve that rigor in project data instead.

## 8. Keyword and entity use

Use the exact game name in important locations where natural:

- title
- H1
- opening copy
- relevant H2s
- image alt text when the image actually shows the game
- internal anchor text
- structured data

Use related concepts and game terminology because they help describe the entity, not because a density target exists.

Never target a fixed keyword-density percentage.

Avoid:

- repeated exact-match phrases in every paragraph
- hidden text
- white-on-white text
- giant footer keyword lists
- irrelevant location modifiers
- autogenerated synonym blocks

## 9. Internal linking

For multi-page sites:

- every important page must be reachable through crawlable `<a href>` links
- use descriptive anchor text
- link from the homepage to useful deeper pages
- link related guide pages to one another where useful
- avoid orphan pages

A page should not exist merely to target another keyword variant.

## 10. External and official links

Link to the canonical official game/developer source for attribution and user trust.

Do not imply affiliation.

Use normal links when editorially appropriate. Do not add `nofollow` automatically to every external link.

## 11. Images

Images should support both users and performance.

Rules:

- meaningful `alt` text for informative images
- empty `alt=""` for purely decorative images
- do not stuff keywords into alt attributes
- define `width` and `height` or reserve aspect ratio to reduce layout shift
- do not lazy-load the likely LCP hero image
- lazy-load below-the-fold screenshots when appropriate
- compress site-owned assets
- prefer modern formats where practical
- use descriptive filenames for site-owned images when practical

The game title in alt text is appropriate only when the image actually depicts that game.

## 12. HTML semantics and crawlability

Production output must include:

- `<html lang="...">`
- semantic HTML5
- crawlable text in server/static HTML for core content
- normal anchor links for important navigation
- no accidental `noindex`
- no content that only appears after an interaction if that content is required for indexing

The heavy game runtime may load after a click. The SEO copy must not depend on the game iframe loading.

## 13. Open Graph and social metadata

Important pages should include accurate:

- `og:title`
- `og:description`
- `og:url`
- `og:image`
- `og:type`
- Twitter/X card fields when useful

Social metadata does not replace title, meta description or canonical.

## 14. Structured data

Use JSON-LD only when it accurately represents visible/current content.

Possible types:

- `VideoGame`
- `BreadcrumbList`
- `FAQPage` when appropriate

Rules:

- game name/developer/platform/status must be accurate
- URLs must point to the intended entity/page
- do not invent ratings, review counts, prices or release dates
- do not expect FAQ rich results for ordinary game sites; the visible FAQ itself is the primary value

## 15. Robots and sitemap

Production output must include:

```text
/robots.txt
/sitemap.xml
```

Requirements:

- sitemap includes every canonical indexable URL and no non-indexable URL
- each non-indexable HTML route emits `noindex,follow` and is omitted from the sitemap
- `pages[].indexable`, HTML robots directives, canonical policy, sitemap membership and hreflang membership agree
- non-indexable routes are omitted from hreflang clusters
- `noindex` pages are not blocked in robots.txt; crawlers must fetch them to see the directive
- robots.txt does not accidentally block production pages/assets required for rendering
- do not put staging or preview URLs in the production sitemap

## 16. Duplicate and thin-page prevention

Do not create pages such as:

```text
/play-game
/play-game-online
/free-game
/game-online
```

when they all satisfy the same intent with near-identical content.

Create a separate route only when it has a distinct user purpose and enough real information to deserve its own page.

Useful support pages that do not meet that bar may remain accessible with `noindex,follow`. `noindex` is an index-budget decision, not a requirement to delete the page.

Avoid scaled doorway content and mass-produced pages with only the game name changed.

## 17. Performance and Core Web Vitals

SEO output must not sacrifice usability.

Priorities:

- site UI should render before the game payload
- lazy-load the heavy runtime after user interaction when possible
- prevent image layout shift
- minimize render-blocking assets
- avoid unnecessary UI frameworks for simple builds
- keep JavaScript small outside the game runtime

Measure production builds when tooling is available. Treat poor LCP/INP/CLS as an optimization issue rather than assuming static HTML automatically means fast.

## 18. Mobile-first validation

Check the real page around:

```text
390px
768px
1440px
```

The mobile page must preserve:

- readable H1
- clear game title and intro
- playable or clearly explained player behavior
- tap-friendly controls
- no horizontal overflow
- useful body copy

If the game itself is not realistically usable on mobile, say `Desktop recommended` rather than making a false mobile-play claim.

## 19. Search Console readiness

Before a production build is marked complete, it should be ready to:

- verify in Google Search Console
- submit sitemap.xml
- request indexing for the canonical homepage when appropriate
- inspect rendered/indexed URL
- monitor queries, impressions, CTR and indexing state

Search Console connection is an operational deployment step, not something to fake in generated code.

## 20. On-Page SEO Gate

A build fails the SEO gate if any of these are true:

- title does not identify the page/game
- homepage H1 does not clearly identify the game/topic
- canonical is missing, wrong or still a placeholder in production
- primary content exists only inside an iframe
- page is thin/filler content around a player
- important images cause avoidable layout shifts or have misleading alt text
- multi-page site has orphan or duplicate-intent pages
- indexability, robots, canonical, sitemap or hreflang signals disagree
- non-indexable HTML page lacks `noindex` or appears in the sitemap
- sitemap/robots are missing from a production deliverable
- structured data contains invented facts
- production page is accidentally noindexed
- keyword stuffing, hidden text or doorway-page patterns are present

Use this result format:

```text
ON-PAGE SEO: PASS | FAIL
Primary intent: <intent>
Primary keyword/entity: <game name / query>
Canonical: <url>
Indexable pages: <count/list>
Blocking SEO issues: <none or list>
```

A project cannot be marked `deployment-ready: YES` while `ON-PAGE SEO: FAIL`.
