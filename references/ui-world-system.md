# Game-Native UI World System

# 1. Purpose

Open WebGame already derives colors and visual DNA from the current game. That is necessary but not sufficient.

A memorable site also needs a **structural UI metaphor**.

Dear Passengers succeeds because its site behaves like an airline operations briefing, not merely because it uses game-matching colors.

The lesson is:

> Theme must be structural, not decorative.

# 2. Build a world, not a skin

Before UI generation, define:

    World metaphor:
    User role:
    Primary document/object:
    Status language:
    Chapter language:
    CTA language:
    Evidence/source language:
    Media caption language:

Examples:

- airline co-op game → flight board / crew briefing
- dressmaking game → atelier ledger / work order / pattern book
- detective game → case file / evidence board
- factory game → operations console / production sheet
- farming game → field journal / seasonal board
- survival game → expedition log / field manual

Do not force a metaphor when the game's identity does not support one.

# 3. UI grammar

For long-form authority pages, a strong repeated grammar is:

    small context/status label
    ↓
    large section heading
    ↓
    short useful explanation
    ↓
    structured facts / cards / media
    ↓
    source / state / next action

This rhythm helps deep SEO pages feel designed rather than bloated.

# 4. Numbered chapters

For a long homepage, consider:

    01 · <entity / world>
    02 · <current state>
    03 · <core loop>
    04 · <guidance>
    05 · <systems>
    06 · <current issues>
    07 · <requirements/platforms>
    08 · <developer>
    09 · <official sources>
    10 · <FAQ>

Names must be game-native, not copied from another site.

# 5. Status labels

Use labels to convey meaning, not decoration.

Useful states:

- OFFICIAL
- VERIFIED
- CURRENT BUILD
- PLAYER REPORT
- FIXED
- UNDER REVIEW
- UNKNOWN
- EVENT UPDATE
- MAINTAINED GUIDE

Do not rely on color alone.

# 6. Media framing

Official screenshots/media can become editorial evidence blocks with:

- contextual caption;
- source/rights note;
- what the image actually demonstrates.

Do not infer unconfirmed mechanics from a screenshot.

# 7. CTA vocabulary

Avoid generic "Learn more" everywhere.

Use a small consistent set that matches the game's world while remaining clear.

Theme must never reduce usability.

# 8. Design acceptance

The site should be recognizable as belonging to the current game even if the logo is hidden.

It fails if it looks like:

- generic Tailwind gaming blog;
- previous generated site with new colors;
- stock-card template;
- keyword site with decorative game wallpaper.

It passes when:

- information architecture;
- section labels;
- facts;
- cards;
- source states;
- image captions;
- CTA copy;
- typography;
- spacing

all participate in the same visual language.
