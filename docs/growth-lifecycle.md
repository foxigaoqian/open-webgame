# Growth Lifecycle for Game Sites

This document converts the one-time "build a site" workflow into an ongoing growth system.

# V0 — Baseline

Capture:

- official facts;
- current SERP;
- competitors;
- user questions;
- game/build state;
- languages;
- canonical entity.

# V1 — Entity establishment

Ship:

- entity homepage;
- central guide/editorial hub for wiki projects;
- FAQ;
- source system;
- core search-intent pages;
- trust/disclosure pages.

# V1.5 — Freshness

Add:

- meaningful dated reports;
- maintained trackers;
- current-build/status handling;
- revision log;
- source/claim ledger.

# V2 — Topic depth

Use:

- Search Console;
- player discussions;
- official patches;
- SERP gaps.

Decision:

    question appears
      → update existing parent first
      → split only when independent demand is clear

# V3 — Locale depth

Separate:

- website language;
- game software language.

Localize entity pages first where appropriate. Expand deep locale content only when there is real demand.

# V4 — Adjacent audience

After the main entity is stable, add genuinely adjacent games/topics.

Do not dilute a new entity site early.

# V5 — Utility / engagement

Add utilities that match the audience:

- trackers;
- checklists;
- calculators;
- planners;
- printable references;
- verified playable pages.

# V6 — Authority moat

Accumulate assets competitors cannot recreate instantly:

- version/build database;
- issue history;
- source ledger;
- correction history;
- query taxonomy;
- original tools/data;
- repeat visitors;
- natural citations.

# Progress by evidence

Do not use:

    Day 30 = V2
    Day 60 = V3

Use:

    evidence threshold
        ↓
    next stage

A fast-rising launch can move quickly. A fading game should not be forced into hundreds of pages.
